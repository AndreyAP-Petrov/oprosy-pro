# Архитектура

## Общая схема

```text
Браузер пользователя
        │ HTTPS
        ▼
Nginx / reverse proxy / УЛЕЙ
        │ HTTP на назначенный PORT
        ▼
Node.js server.js
        ├── /api/auth — вход, активация, профиль, 2FA, пользователи
        ├── /api/app  — статистики, таблицы, общая сводка
        ├── /api/health
        └── public/   — клиентский интерфейс
                │
                ▼
Постоянное хранилище OPROSY_DATA_DIR
        ├── db.json
        └── .master-key
```

## Хранение

Код релиза и пользовательские данные должны находиться отдельно.

В УЛЬЕ рекомендуемая схема:

```text
project/
├── current/          # сменяемый код релиза
├── releases/         # предыдущие релизы
└── data/             # постоянные данные
```

При запуске из каталога `current` приложение автоматически пытается использовать `../data`.

## Пользователи

- регистрация через публичную форму отсутствует;
- OWNER создаёт учётную запись и получает одноразовый код активации;
- пользователь сам задаёт пароль;
- пользователь подключает собственную TOTP-2FA;
- каждому аккаунту назначается постоянный ID вида `usr_...`;
- в закрытой версии все активные участники имеют роль OWNER.

## Доступ к статистикам

- данные API доступны только по действующей серверной сессии;
- публичная статистика видна всем зарегистрированным участникам команды;
- приватная статистика видна её владельцу и системному владельцу;
- клиентский интерфейс не является границей безопасности: проверка выполняется сервером.

## Таблицы

Стандартные ручные поля:

- коллектор;
- показы;
- клики;
- собрано анкет;
- потрачено без НДС;
- всего необходимо анкет;
- статус.

Вычисляемые значения обновляются в браузере в реальном времени и сохраняются на сервер.

## Ограничения текущей архитектуры

- файловая JSON-база рассчитана на небольшую команду и умеренную частоту изменений;
- нет распределённой блокировки для нескольких экземпляров приложения;
- нет отдельной реляционной базы и полноценного журнала аудита;
- для горизонтального масштабирования нужен PostgreSQL/Redis или эквивалентный контур.
