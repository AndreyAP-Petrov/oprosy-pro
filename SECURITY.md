# Политика безопасности

## Не публикуйте

- пароли;
- коды активации;
- TOTP-секреты и QR-коды;
- `db.json`;
- `.master-key`;
- реальные переменные окружения;
- персональные выгрузки пользователей;
- серверные IP, SSH-пароли и приватные ключи в issues.

## Хранение паролей

Пароли сохраняются в виде необратимых хэшей `scrypt`. Восстановить исходный пароль из базы нельзя; используется сброс доступа.

## 2FA

TOTP-секреты шифруются AES-256-GCM с ключом `DATA_ENCRYPTION_KEY` либо локальным `.master-key`.

## Сессии

Сессия передаётся через cookie с параметрами `HttpOnly` и `SameSite=Strict`. Для production обязательно использовать HTTPS.

## Сообщение об уязвимости

Не создавайте публичный issue с секретами или инструкцией эксплуатации. Передайте сведения владельцу репозитория приватным каналом.
